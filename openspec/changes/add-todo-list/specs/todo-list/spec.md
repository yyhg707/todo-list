# Spec Delta: todo-list

## Purpose

定义待办清单的可验收行为：条目如何创建、修改、完成、删除、筛选与统计，
以及本地数据损坏时的降级方式。所有行为都在浏览器本地完成，不发起网络请求。

## ADDED Requirements

### Requirement: 新增条目

系统 SHALL 在提交非空文本时创建一条未完成条目，去除首尾空白并把连续空白压缩为一个空格；
文本长度 MUST 在 1 到 200 个字符之间，空文本、纯空白或超长输入不得产生条目。

#### Scenario: 正常新增
- **WHEN** 用户输入「买 电池」并提交
- **THEN** 列表新增一条内容为「买 电池」的未完成条目，输入框清空

#### Scenario: 空输入
- **WHEN** 用户输入纯空格并提交
- **THEN** 不新增条目，页面提示需要输入 1 到 200 个字符

#### Scenario: 超长输入
- **WHEN** 输入 201 个字符并提交
- **THEN** 不新增条目，已有条目不受影响

### Requirement: 完成状态

系统 SHALL 允许切换条目的完成状态，并在统计中反映；切换 MUST 只影响被点击的那一条。

#### Scenario: 标记完成
- **WHEN** 点击未完成条目的勾选按钮
- **THEN** 该条目标记为已完成，未完成计数减一、已完成计数加一

#### Scenario: 取消完成
- **WHEN** 再次点击同一条目的勾选按钮
- **THEN** 恢复为未完成，统计同步变化

### Requirement: 编辑与删除

系统 SHALL 允许修改条目文本与删除条目；编辑为空文本 MUST 保留原内容；删除 MUST 只移除目标条目。

#### Scenario: 编辑为空
- **WHEN** 双击条目，清空文本后按回车
- **THEN** 保留修改前的内容，不产生空条目

#### Scenario: 删除条目
- **WHEN** 点击某条目的删除按钮
- **THEN** 该条目消失，其余条目与顺序不变

### Requirement: 筛选与统计

系统 SHALL 提供全部、未完成、已完成三种筛选，并在统计区显示总数、未完成数与已完成数；
筛选 MUST NOT 修改数据本身。

#### Scenario: 筛选未完成
- **WHEN** 选择「未完成」
- **THEN** 只显示未完成条目，统计区仍显示全量数字

#### Scenario: 清除已完成
- **WHEN** 存在已完成条目时点击「清除已完成」
- **THEN** 已完成条目被移除，未完成条目保持不变，无已完成条目时按钮不可用

### Requirement: 本地持久化与容错

系统 SHALL 把条目保存在浏览器本地存储，刷新后恢复；读取时 MUST 校验结构并丢弃非法或重复条目；
存储内容损坏或不可用 MUST NOT 导致页面崩溃或白屏，应回退为空列表并提示。

#### Scenario: 刷新恢复
- **WHEN** 新增条目后刷新页面
- **THEN** 条目仍在，顺序与内容不变

#### Scenario: 存储损坏
- **GIVEN** 本地存储中被写入非法 JSON
- **WHEN** 打开页面
- **THEN** 页面正常显示空态并提示数据未能读取，不出现脚本错误

#### Scenario: 存储不可用
- **GIVEN** 浏览器禁用了本地存储
- **WHEN** 用户新增条目
- **THEN** 当前页面仍可操作，并提示本次修改不会被保存

### Requirement: 用户文本按纯文本渲染

系统 MUST 把用户输入作为文本节点插入页面，不得解释为 HTML；页面 MUST 配置内容安全策略，
禁止内联脚本与外部连接。

#### Scenario: 输入含标签的文本
- **WHEN** 用户输入 `<img src=x onerror=alert(1)>`
- **THEN** 列表按原样显示这段文字，不加载图片、不执行脚本

### Requirement: 键盘与读屏可用

系统 SHALL 支持键盘完成主要操作：回车提交、编辑态回车保存与 Esc 取消；
状态变化 SHALL 通过 `aria-live` 区域播报，筛选按钮 SHALL 使用 `aria-pressed` 表示当前选择。

#### Scenario: 仅用键盘完成一条待办
- **WHEN** 用户只用键盘输入、提交、切换完成并删除
- **THEN** 每一步都可完成，焦点顺序合理，状态变化有文字反馈
