# Design: 待办清单工程化重写

## Context

初版是一个 `index.html`，HTML、CSS、脚本混在一起，逻辑与 DOM 无法分开测试。
数据用 `JSON.parse(localStorage.getItem('todos'))` 直接读取，内容异常时整页报错。
本 change 要在不引入框架的前提下，把可测试性与失败路径补上。

## Goals / Non-Goals

### Goals
- 逻辑可单测：不依赖浏览器即可验证增删改查与存储容错
- 用户输入不进入 HTML 拼接，避免自注入
- 键盘与读屏可用：主要操作不依赖鼠标
- 任何人执行 `npm test` 得到同样结果

### Non-Goals
- 不追求离线安装（PWA）、不做主题切换
- 不做撤销/重做与多选批量操作

## Decisions

### 决策 1：逻辑与 DOM 分离

**选项**：全部写在页面脚本里 / 抽成 `todos.js` 纯函数 / 引入状态管理库

**选择**：抽成 `todo.js` 纯函数

**理由**：
- 纯函数输入输出确定，`node:test` 可直接覆盖，无需浏览器或 DOM 模拟
- 不引入依赖，页面仍是静态文件，GitHub Pages 可直接托管
- DOM 层只剩事件绑定与渲染，出现问题时边界清楚

### 决策 2：id 用递增整数而不是时间戳

**选项**：`Date.now()` / 随机 UUID / 当前最大 id + 1

**选择**：当前最大 id + 1

**理由**：
- 同一毫秒内连续添加不会撞 id
- 测试可预测，不依赖时钟
- 数据量级小，不需要全局唯一

### 决策 3：存储解析失败回退空列表

**选项**：报错中断 / 静默忽略 / 回退空列表并提示

**选择**：回退空列表并提示

**理由**：
- 直接 `JSON.parse` 会在数据损坏时整页白屏，用户无法自救
- 逐条校验（id 为正整数、文本非空、去重），丢弃坏条目而不是整表丢弃
- 提示语说明「本地数据未能读取」，避免用户以为数据被悄悄清空

### 决策 4：渲染用 DOM API，不用 innerHTML 拼接

**选项**：模板字符串 + `innerHTML` / `createElement` + `textContent`

**选择**：`createElement` + `textContent`

**理由**：
- 用户文本永远作为文本节点插入，不存在 HTML 注入路径
- 虽然初版有 `escapeHtml`，但依赖每个调用点都记得转义，容易漏
- 配合 CSP（禁止内联脚本与外部连接）形成两层防护

## Risks / Trade-offs

- 纯函数式写法每次返回新数组，数据量大时有拷贝开销。当前规模（几百条）可忽略。
- 手写 DOM 比模板字符串啰嗦。用 `buildItem` 集中处理，可读性可接受。
- 浏览器存储不可用（隐私模式）时功能降级为「本次有效」。已在界面上明确提示。
